B. Testing how the system performs under various conditions
C. Testing user interfaces
D. Testing database schemas
✓ Correct Answer: B
Explanation: Non-functional testing evaluates aspects like performance, security, usability, reliability, and scalability—not what the system does, but how well it performs its functions.


12. Which of the following is a static testing technique?
A. Unit Testing
B. Integration Testing
C. Code Review
D. System Testing
✓ Correct Answer: C
Explanation: Static testing examines work products without executing code. Code reviews, walkthroughs, and static analysis are static techniques. Dynamic testing (A, B, D) requires code execution.


13. What does "Shift Left" testing mean?
A. Moving testing activities earlier in the development lifecycle
B. Moving testing to production
C. Testing only on the left side of the screen
D. Testing after the release
✓ Correct Answer: A
Explanation: Shift Left emphasizes starting testing activities earlier in the SDLC to find and fix defects sooner, when they are cheaper to resolve. This includes requirements validation, design reviews, and early automation.


14. Which test design technique involves dividing input data into classes that are expected to behave similarly?
A. Boundary Value Analysis
B. Equivalence Partitioning
C. Decision Table Testing
D. State Transition Testing
✓ Correct Answer: B
Explanation: Equivalence Partitioning divides input domains into classes of equivalent data. Testing one value from each partition assumes it represents the whole class, reducing redundant test cases.


15. Boundary Value Analysis (BVA) focuses on:
A. Random data inputs
B. Values at the edges of equivalence partitions
C. Only positive test scenarios
D. Internal code structure
✓ Correct Answer: B
Explanation: BVA tests values at the boundaries between partitions because defects often occur at edges (e.g., minimum, maximum, just below/above boundaries). It's typically used with Equivalence Partitioning.


16. What is the main purpose of Continuous Integration (CI) in QA?
A. To deploy software to production automatically
B. To merge code changes frequently and verify them with automated builds and tests
C. To write documentation continuously
D. To perform manual testing every day
✓ Correct Answer: B
Explanation: CI involves frequently integrating code changes into a shared repository, where automated builds and tests run. This catches integration issues early and maintains code quality.


17. Which of the following is an example of a defect priority (not severity)?
A. Critical
B. High
C. Medium
D. All of the above can be priorities
✓ Correct Answer: D
Explanation: Priority indicates how urgently a defect needs to be fixed (business urgency). Severity indicates the impact on functionality. Both use similar scales but measure different things.


18. What does Code Coverage measure?
A. The percentage of requirements covered by tests
B. The percentage of code executed by tests
C. The number of bugs found per test
D. The time taken to execute tests
✓ Correct Answer: B
Explanation: Code coverage measures how much of the source code is exercised by the test suite. Common types include statement coverage, branch coverage, and path coverage.


19. Which testing type evaluates the system's behavior under expected load conditions?
A. Stress Testing
B. Load Testing
C. Volume Testing
D. Spike Testing
✓ Correct Answer: B
Explanation: Load testing evaluates system performance under expected/normal load conditions. Stress testing tests beyond normal capacity. Volume testing tests with large data volumes. Spike testing tests sudden load increases.


20. What is a Test Oracle?
A. A person who predicts test outcomes
B. A mechanism for determining whether a test has passed or failed
C. A database of all test cases
D. A tool that generates test data
✓ Correct Answer: B
Explanation: A test oracle provides the expected result against which the actual result is compared. It can be documentation, existing systems, or automated oracles that determine pass/fail status.


21. In Risk-Based Testing, what determines the priority of test cases?
A. The order in which features were developed
B. The likelihood and impact of potential failures
C. The preferences of the test manager
D. Alphabetical order of feature names
✓ Correct Answer: B
Explanation: Risk-based testing prioritizes tests based on the risk level (probability of failure × impact of failure). High-risk areas receive more testing focus.


22. What is the purpose of the Traceability Matrix?
A. To track code changes
B. To map requirements to test cases, ensuring all requirements are tested
C. To assign tasks to testers
D. To calculate test coverage of code statements
✓ Correct Answer: B
Explanation: A Requirements Traceability Matrix (RTM) links requirements to test cases, design elements, and code. It ensures test coverage of requirements and helps impact analysis when requirements change.


23. Which of the following best describes Unit Testing?
A. Testing the complete integrated system
B. Testing individual components or modules in isolation
C. Testing the user interface
D. Testing system security
✓ Correct Answer: B
Explanation: Unit testing verifies the smallest testable parts of an application (functions, methods, classes) independently from the rest of the system, typically performed by developers.


24. What is Pair Testing?
A. Testing two applications simultaneously
B. Two team members working together to test the same feature
C. Testing on two different browsers
D. Testing with two different test data sets
✓ Correct Answer: B
Explanation: Pair testing involves two people (often a tester and developer, or two testers) working together at one workstation to test software, combining knowledge and perspectives in real-time.


25. Which document describes the detailed steps to execute a specific test?
A. Test Plan
B. Test Strategy
C. Test Case
D. Requirement Specification
✓ Correct Answer: C
Explanation: A test case specifies inputs, execution conditions, and expected results for a particular test objective. Test plans are higher-level documents; test strategies define overall approaches.


26. What does "Validation" mean in software quality?
A. Are we building the product correctly?
B. Are we building the correct product?
C. Is the code optimized?
D. Is the documentation complete?
✓ Correct Answer: B
Explanation: Validation checks whether the software meets user needs/requirements (the right product). Verification checks whether the software conforms to specifications (built correctly).


27. Which tool type is used to perform static analysis on source code without executing it?
A. Performance testing tool
B. Static analysis tool
C. Test management tool
D. Defect tracking tool
✓ Correct Answer: B
Explanation: Static analysis tools scan source code to find potential defects, security vulnerabilities, and code quality issues without running the program (e.g., SonarQube, PMD, ESLint).


28. What is the primary purpose of Acceptance Testing?
A. To find syntax errors in code
B. To determine if the system meets business requirements and is ready for deployment
C. To test individual modules
D. To measure system performance
✓ Correct Answer: B
Explanation: Acceptance testing (User Acceptance Testing - UAT) verifies that the system meets business requirements and is acceptable to end users/customers for deployment.


29. Which of the following is a characteristic of good test cases?
A. They are vague and general
B. They are repeatable and have clear expected results
C. They require no setup or preconditions
D. They test multiple unrelated features at once
✓ Correct Answer: B
Explanation: Good test cases are clear, specific, repeatable, traceable to requirements, and have unambiguous expected results. They should include preconditions, steps, and postconditions.


30. What does ISTQB stand for?
A. International Software Testing Qualifications Board
B. International Standard for Testing Quality Benchmarks
C. Institute for Software Testing and Quality Business
D. International Society for Testers and Quality Builders
✓ Correct Answer: A
Explanation: ISTQB is the International Software Testing Qualifications Board, which provides internationally recognized certifications for software testers.


31. What is Exploratory Testing?
A. Testing without any planning or documentation
B. Simultaneous learning, test design, and test execution
C. Automated testing of user interfaces
D. Testing performed only by end users
✓ Correct Answer: B
Explanation: Exploratory testing involves designing and executing tests simultaneously while learning about the system. Testers use their domain knowledge to actively explore the application.


32. Which of the following is NOT a level of testing in the traditional testing pyramid?
A. UI Tests
B. Unit Tests
C. Integration Tests
D. Deployment Tests
✓ Correct Answer: D
Explanation: The testing pyramid consists of Unit tests (base), Integration/Service tests (middle), and UI/E2E tests (top). Deployment tests are not a standard level of the testing pyramid.


33. What is Test-Driven Development (TDD)?
A. Writing tests after coding is complete
B. Writing tests before writing the corresponding code
C. Testing only when defects are reported
D. Developing tests using automation tools only
✓ Correct Answer: B
Explanation: TDD follows a "Red-Green-Refactor" cycle: write a failing test first, write minimal code to pass it, then refactor. Tests drive the design and implementation.


34. Which testing approach involves testing the system with knowledge of its internal structure and code?
A. Black-box testing
B. White-box testing
C. Gray-box testing
D. Ad-hoc testing
✓ Correct Answer: B
Explanation: White-box testing (clear box/structural testing) requires knowledge of internal code structure. Testers design cases based on code paths, conditions, and data flows.


35. What is the primary purpose of a Defect/Bug Report?
A. To assign blame to developers
B. To communicate defect information clearly for reproduction and fixing
C. To delay the project
D. To replace test cases
✓ Correct Answer: B
Explanation: A good bug report provides clear, objective information about a defect (steps to reproduce, expected vs. actual behavior, environment) to help developers understand and fix it efficiently.


36. Which of these is an example of a non-functional requirement?
A. The system shall allow users to create an account
B. The system shall process 1000 transactions per second
C. The system shall display user profiles
D. The system shall send email notifications
✓ Correct Answer: B
Explanation: Performance requirements (transactions per second) are non-functional. Functional requirements describe what the system does. Non-functional requirements describe how the system performs.


37. What does "Smoke Testing" refer to?
A. Exhaustive testing of all features
B. A preliminary test to reveal simple failures severe enough to reject a build
C. Testing under extreme heat conditions
D. Testing that produces smoke effects in UI
✓ Correct Answer: B
Explanation: Smoke testing (build verification testing) runs minimal tests to verify that the basic functionality works. If smoke tests fail, the build is rejected before further testing.


38. Which quality model defines characteristics like Functionality, Reliability, Usability, Efficiency, Maintainability, and Portability?
A. CMMI
B. ISO/IEC 25010 (SQuaRE)
C. Six Sigma
D. ITIL
✓ Correct Answer: B
Explanation: ISO/IEC 25010 (replacing ISO 9126) defines software product quality characteristics including functional suitability, reliability, usability, performance efficiency, compatibility, security, maintainability, and portability.


39. What is the primary difference between Verification and Validation?
A. There is no difference
B. Verification checks conformance to specifications; Validation checks fitness for use
C. Verification is done by testers; Validation by developers
D. Verification is automated; Validation is manual
✓ Correct Answer: B
Explanation: Verification (Are we building the product correctly?) checks against specifications. Validation (Are we building the correct product?) checks against user needs and intended use.


40. In which phase of the SDLC is the cost of fixing a defect typically lowest?
A. Testing
B. Requirements
C. Production/Maintenance
D. Design
✓ Correct Answer: B
Explanation: Defects found during requirements phase are cheapest to fix. Costs increase exponentially as the defect progresses through design, coding, testing, and is most expensive after production release.


41. What is Alpha Testing?
A. Testing performed by end users at the developer's site
B. Testing performed by end users at their own location
C. Automated regression testing
D. Performance testing with alpha software
✓ Correct Answer: A
Explanation: Alpha testing is performed by internal users/customers at the developer's site before release. Beta testing is performed by end users at their own locations.


42. Which tool is primarily used for managing and tracking defects?
A. JMeter
B. Jira
C. Jenkins
D. Selenium
✓ Correct Answer: B
Explanation: Jira is a widely used issue and project tracking tool for defect management. JMeter is for performance testing, Jenkins for CI/CD, and Selenium for browser automation.


43. What does "Sanity Testing" verify?
A. The entire application functionality
B. Whether specific functionality works roughly as expected after minor changes
C. The security of the application
D. The database integrity only
✓ Correct Answer: B
Explanation: Sanity testing is a narrow regression test focused on one or a few functionality areas to verify that recent changes haven't broken related functionality. It's deeper than smoke testing but narrower than full regression.


44. What is the main purpose of a Test Strategy document?
A. To provide day-to-day test execution instructions
B. To define the high-level approach, objectives, and scope of testing for the organization/project
C. To log defects found during testing
D. To record test results
✓ Correct Answer: B
Explanation: A Test Strategy is a high-level document outlining overall testing objectives, scope, levels, types, and approach. Test plans are more specific to a project/release, while test cases guide daily execution.


45. Which approach involves writing tests based on the expected behavior of the system from the user's perspective?
A. Behavior-Driven Development (BDD)
B. Data-Driven Testing
C. Keyword-Driven Testing
D. Model-Based Testing
✓ Correct Answer: A
Explanation: BDD uses natural language constructs (Given-When-Then) to describe expected behavior from the stakeholder's perspective, bridging communication between technical and non-technical team members.


46. What is a "flaky test"?
A. A test that always passes
B. A test that produces inconsistent results (passes and fails) without code changes
C. A test that never runs
D. A test that only runs on weekends
✓ Correct Answer: B
Explanation: Flaky tests produce non-deterministic results—sometimes passing, sometimes failing without code changes. They're problematic because they reduce confidence in test suites and CI/CD pipelines.


47. Which testing technique is based on the tester's experience and intuition to find defects?
A. Scripted testing
B. Error Guessing
C. Equivalence Partitioning
D. Decision Table
✓ Correct Answer: B
Explanation: Error guessing is an experience-based technique where testers use intuition and experience to guess where defects are likely to occur, often supplementing formal techniques.


48. What is the main benefit of Test Automation?
A. It eliminates the need for manual testing completely
B. It enables repeatable, fast execution of regression tests
C. It finds more bugs than manual testing
D. It requires no maintenance
✓ Correct Answer: B
Explanation: Automation excels at repeated execution (especially regression) with speed and consistency. It doesn't eliminate manual testing or necessarily find more bugs, and it requires significant maintenance.


49. Which of the following is a key metric for measuring test effectiveness?
A. Number of test cases written
B. Defect Detection Percentage (DDP)
C. Number of meetings attended
D. Lines of code written
✓ Correct Answer: B
Explanation: Defect Detection Percentage measures what percentage of total defects were found during testing versus post-release. It's a key effectiveness metric. Number of test cases is an activity metric, not effectiveness.


50. What is the purpose of a "Definition of Done" (DoD) in Agile QA?
A. To define when a user story or feature meets all quality criteria and is releasable
B. To end the project when resources run out
C. To define daily working hours
D. To assign specific defects to developers
✓ Correct Answer: A
Explanation: The Definition of Done is a shared understanding of what it means for work to be complete, including coding, testing, documentation, and review criteria. It ensures consistent quality and "releasable" increments.
